# Polza Agency - техническое задание

Проект решает три технические задачи:

1. импортирует `page_001.json ... page_020.json` в PostgreSQL;
2. показывает компании на серверной странице Next.js `/companies`;
3. загружает `review.csv` в отдельную таблицу и формирует отчёт `ANOMALIES.md`.

## Что найдено в данных

- JSON-файлов: **20**;
- исходных строк: **1000**;
- уникальных компаний: **994**;
- полных дублей между страницами: **6**;
- строк данных в `review.csv`: **207**;
- строк с блокирующими ошибками: **28**;
- строк только с предупреждениями: **14**.

Главный сюрприз `review.csv` - шесть записей `c_900006...c_900011`, которые выглядят новыми, но совпадают с компаниями основной выгрузки по названию без пунктуации, категории, городу, адресу, рейтингу, числу отзывов, сайту и телефону. Подробности и все остальные отклонения находятся в [`ANOMALIES.md`](./ANOMALIES.md).

## Стек

- Next.js App Router + TypeScript;
- PostgreSQL 17;
- `pg`, без ORM;
- Docker Compose;
- Node.js test runner;
- GitHub Actions.

## Быстрый запуск

Требуются Node.js 20.9+ и Docker Desktop.

### 1. Установить зависимости

```bash
npm install
```

### 2. Создать файл окружения

Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

macOS/Linux:

```bash
cp .env.example .env.local
```

В `.env.example` используются только локальные тестовые данные:

```env
DATABASE_URL=postgresql://polza:polza@localhost:5432/polza
DATABASE_SSL=false
```

### 3. Запустить PostgreSQL

```bash
docker compose up -d db
docker compose ps
```

Схема из `db/schema.sql` применяется при первом создании volume. Её также можно применить вручную:

```bash
npm run db:schema
```

### 4. Импортировать JSON

Файлы из `data_pack.zip` уже находятся в `data/`.

```bash
npm run import:pages -- --data-dir=./data --replace
```

Ожидаемый итог:

```text
Файлов обработано: 20
Строк прочитано: 1000
Компаний в БД: 994
Обновлено/дедуплицировано: 6
```

Флаг `--replace` очищает предыдущий результат полной загрузки. Без него используется UPSERT, поэтому повторный запуск не создаёт новые дубли.

### 5. Выполнить аналитические запросы

```bash
npm run check:db
```

Исходные запросы находятся в `db/queries.sql`, а контрольные результаты - в `artifacts/sql-results.md`.

### 6. Загрузить и проверить review.csv

```bash
npm run import:review -- --file=./data/review.csv --report=./ANOMALIES.md --replace
```

Скрипт:

- читает CSV с учётом кавычек и запятых внутри полей;
- сохраняет все строки в отдельную таблицу `review_rows`;
- не изменяет `companies`;
- хранит исходные и нормализованные значения;
- сохраняет массив ошибок для каждой строки;
- сопоставляет повторы с основной выгрузкой;
- заново формирует `ANOMALIES.md`.

### 7. Запустить интерфейс

```bash
npm run dev
```

Открыть:

```text
http://localhost:3000/companies
```

Примеры URL:

```text
/companies
/companies?search=орион
/companies?city=москва
/companies?search=сервис&city=казань&page=2
```

## Задача 1: импорт и схема

### Структура данных

Реальные JSON-файлы имеют объект-обёртку с массивом компаний. Импортёр также поддерживает массив в корне и типовые поля `data`, `items`, `results`, `companies`, чтобы не зависеть от одной формы API-ответа.

Основная таблица `companies` хранит:

- исходный `external_id`;
- отображаемые и нормализованные поля;
- рейтинг и число отзывов с SQL-ограничениями;
- исходный JSON в `raw_data`;
- источник и номер строки;
- уникальный SHA-256 `dedupe_key`.

### Дедупликация

Приоритет идентичности:

1. `external_id`;
2. email + название;
3. телефон + название;
4. домен сайта + название;
5. название + город + адрес.

В приложенной выгрузке все шесть дублей имеют одинаковый `external_id`. На `external_id` и `dedupe_key` установлены уникальные индексы.

### Индексы

- GIN `pg_trgm` для поиска по `name_normalized`;
- B-tree по городу и категории;
- частичные индексы по сайту, телефону и числу отзывов;
- уникальные индексы для внешнего id и ключа дедупликации.

### SQL-запросы

`db/queries.sql` содержит:

1. топ-5 категорий по количеству компаний;
2. средний рейтинг по городам среди компаний с 10+ отзывами;
3. долю компаний с сайтом по категориям.

## Задача 2: `/companies`

Страница реализована Server Component:

- PostgreSQL читается только на сервере;
- поиск, фильтр и пагинация выполняются SQL-запросами;
- все пользовательские значения передаются параметрами `$1...$n`;
- фильтры сохраняются в URL при переходе между страницами;
- есть loading, error и empty состояния;
- таблица адаптирована под узкий экран.

Секретов в репозитории нет: используется только `.env.example`, а `.env.local` исключён из Git.

## Задача 3: review.csv

Проверяются:

- пустые строки и неверное число столбцов;
- отсутствующие/необычные id и дубли внутри CSV;
- полные повторы основной выгрузки;
- замаскированные дубли с другим id;
- сдвиг столбцов;
- неизвестные категории и города;
- опечатки, регистр, латиница и повреждённая кодировка города;
- формат и диапазон рейтинга;
- целочисленность и неотрицательность числа отзывов;
- сайты и телефоны;
- общие контакты у разных компаний.

Невалидные значения не исправляются молча. Например, `45.5` не округляется до 45, а `htp://...` не превращается автоматически в корректный URL.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Полная локальная проверка:

```bash
npm run verify
npm run import:pages -- --data-dir=./data --replace
npm run import:review -- --file=./data/review.csv --report=./ANOMALIES.md --replace
npm run check:db
```

В проекте есть 12 unit-тестов для:

- нормализации текста, email, телефона и сайта;
- стабильности ключа дедупликации;
- CSV с кавычками и пустыми строками;
- разных JSON-обёрток;
- извлечения компании;
- замаскированного дубля;
- запрета неявного округления `reviews_count`.

CI находится в `.github/workflows/ci.yml`: он поднимает PostgreSQL, запускает проверки, импорт реальных данных и production build.

## Как проверял

Подробный текст находится в `evidence/HOW_I_CHECKED.md`. TypeScript-extractor был прогнан по всем реальным JSON-файлам: 1000 строк, 994 уникальные компании и 6 дублей. Отдельно выполнены 12 unit-тестов и полный анализ 207 строк `review.csv`.

Требуемые скриншоты необходимо сделать после локального запуска по инструкции `evidence/CHECKLIST.md`. В архив намеренно не добавлены сгенерированные макеты, которые могли бы выглядеть как доказательство реально запущенного Next.js/PostgreSQL.
