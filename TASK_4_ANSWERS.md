# Задача 4. Вайбкод / LLM-стек

## 1. Выбор IDE и LLM сейчас и изменения за последние полгода

Основной редактор - VS Code: в нём я контролирую структуру проекта, Git и команды в терминале. Cursor использую, когда нужно быстро разобраться в нескольких связанных файлах или внести согласованные изменения по проекту, а ChatGPT - для обсуждения архитектуры, поиска причины ошибки и ревью решения. Раньше чаще давал модели крупную задачу целиком, сейчас разбиваю работу на небольшие шаги, заранее задаю ограничения и после каждого изменения проверяю diff, типы и тесты.

## 2. Сколько и каких подписок хватает

Для моего текущего объёма работы достаточно одной постоянной платной подписки - ChatGPT Plus. VS Code использую бесплатно, а Cursor - в бесплатном режиме; при месяце с большим количеством многофайловых задач можно временно подключить Cursor Pro. Держать несколько дорогих подписок одновременно без понятной нагрузки не считаю необходимым.

## 3. Как сравниваю две новые модели или инструмента

Не только по ощущениям. Даю обоим одинаковые задачи: найти причину бага, добавить небольшую функцию с тестами и сделать рефакторинг без изменения поведения. Сравниваю количество итераций до рабочего результата, точность соблюдения ограничений, объём лишних изменений, качество объяснения и итоговый diff. Скорость учитываю, но предсказуемость и число ручных исправлений важнее.

## 4. Какие тесты нужны для новой функции

Минимально проверяю основной успешный сценарий, граничные значения, пустые и некорректные входные данные и ожидаемые ошибки. Для исправления бага сначала полезен регрессионный тест, который воспроизводит проблему. Если функция работает с базой, нужны интеграционные проверки записи, чтения, ограничений, транзакции и повторного запуска; для внешнего API - таймаут, ошибочный статус и неожиданный формат ответа.

## 5. Какие разрешения даю coding-agent и почему

Агенту можно дать чтение репозитория, изменение файлов в отдельной ветке, запуск линтера, тестов, сборки и локальных контейнеров. Доступ к тестовой БД допустим, если там нет production-данных и секретов. Без отдельного подтверждения нельзя давать production-ключи, разрешать deploy, удаление данных, изменение доступов или выполнение разрушительных команд. Такой уровень позволяет автоматизировать рутину, но оставляет необратимые действия под контролем разработчика.

## 6. Автотесты и CI/CD

Автотесты пишу для бизнес-логики, преобразования данных, критичных интеграций и найденных багов. Перед merge обязательно должны пройти lint, typecheck, unit-тесты и production build; для проекта с PostgreSQL - также интеграционный импорт на временной БД и проверка SQL/миграций. Перед deploy дополнительно проверяются переменные окружения, отсутствие секретов, успешность сборки и возможность отката. В репозитории это оформлено workflow `.github/workflows/ci.yml`.
